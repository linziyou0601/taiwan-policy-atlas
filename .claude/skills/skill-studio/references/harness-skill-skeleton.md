# Harness Skill 骨架

Harness 型 skill 之 SKILL.md 章節骨架。建立或改寫 Harness 型 skill 時，先依本骨架起稿再填入領域內容。必要章節的集合與順序跨 skill 一致。「執行步驟」內的步驟名與步數由各 skill 依領域自訂。領域需要的選用章節（例如「匯出」）置於執行步驟與停止條件之間，章名先登記到 [section-dictionary](section-dictionary.md)。

## 章節骨架

```markdown
---
name: {domain}
description: {做什麼 + 自動判斷什麼 + 於何種意圖時應主動建議使用}
---

# {顯示名}

## 用途

{職責一段、sub-mode 表、產出去向}

## 輸入

| 輸入 | 必要性 | 說明 | 預設 |
|---|---|---|---|

## 執行步驟

### 前置確認

{讀取哪些規則與治理檔、偵測既有 artifact、有 sub-mode 時依 source-to-submode 路由並回報 route summary}

完成判準：{可勾稽條件}

### {領域步驟 1..n}

{每步一段，祈使語氣}

完成判準：{可勾稽條件}

### 結案

{完整性檢查、產出 report 或 handoff、附後續步驟可直接貼上的 prompt}

完成判準：{可勾稽條件}

## 停止條件

## 委派

| 子任務 | 預設執行者 | 備註 |
|---|---|---|

## 產出

| 產物 | 位置 |
|---|---|

## 完整性檢查

## 參考型錄
```

## 章節約定

| 章節 | 約定 |
|---|---|
| 用途 | 有 sub-mode 時含 sub-mode 表。邊界由停止條件與完成判準承載 |
| 輸入 | 標準 4 欄表。`gate` 一律列入，取值寫在專案的共用規則 |
| 執行步驟 | 首步固定「前置確認」、末步固定「結案」。每步以「完成判準：」結束，判準須可判定完成與否、且對範圍窮盡。「每個受影響模組已列 row」是合格判準，「已充分盤點」不是 |
| 停止條件 | 只列領域特定條件，各 skill 共用的阻塞事項寫在專案的共用規則 |
| 委派 | 標準 3 欄表，列情境命中才啟用的特化委派，備註欄寫啟用情境或委派時必附事項。inline 與 sub-agent 的取捨寫在專案的共用規則，執行步驟只寫情境命中時的委派 |
| 產出 | 標準 2 欄表。report 與 handoff 的結構寫在對應的 contract |
| 完整性檢查 | 可逐列打勾。專案有共用的完成檢查時，引用後只列領域額外項 |
| 參考型錄 | 每檔一行：markdown link 加一句用途。跨 skill 引用寫 Skill `/xxx` |

## 骨架外事項

- 模型能力與 context 規劃、防幻覺底線、severity 取值由專案的共用規則提供時，SKILL.md 引用即可，出處寫在各 skill 的參考型錄。
- 章節標題譯名依 [section-dictionary](section-dictionary.md)。
- 技術識別詞保留英文，敘述文字用正體中文完整句。內容一律描述 skill 的現在樣貌（現況陳述），遷移殘影詞與空話詞由 `scripts/quick_validate.py --structure` 的文風檢查列舉並攔截，敘事段落另受自動套用之文風 rule 治理。
