# 派工與核對

編碼由主 session 負責，subagent 只負責可以分開驗收的工作。subagent 的結果一律由主 session 核對後才寫入 repo，主 session 對最後的資料負責。

## 派工原則

- 同時最多兩個 subagent。
- subagent 不寫入 repo 的檔案。草稿與抽查結果寫在 session 的暫存目錄，主 session 閱讀後再寫入各層 TSV。
- 主 session 派工前記錄輸入素材的內容雜湊，接收結果時比對原始素材，確認 subagent 沿用讀取的內容。素材有改動時，先確認修改來源與影響，再採用草稿或抽查結果。
- 派工訊息要寫明：要閱讀的 skill 步驟與判準表、範圍、輸出目錄，以及「只列出不一致的地方，一致的不必列出」。草稿使用各層 TSV 的表頭，主 session 核對後直接寫入該層。

<br>

## 抽查範圍

每次編碼完成後至少抽查：

1. 每位候選人五則主張回到公報頁面，逐字比對原文欄。
2. 每個有配題的面向一筆配題，重新檢視立場與理由是否符合 `rubric-stance.tsv`。
3. 全部的反對、強烈反對立場，以及全部子題的配題。
4. 每位候選人五則主張的每條具體度評分，對照 `rubric-specificity.tsv` 的級距描述。
5. 全部現任政府計畫標為是的主張，確認不是已完成的政績。

<br>

## 抽查結果的處理

subagent 回報的每筆不一致，主 session 逐筆回到原文或影像判斷：

| 判斷 | 處理 |
|---|---|
| 原編碼正確 | 保留原編碼，判斷依據補充到該列的理由欄，轉錄段落寫在 `transcripts.tsv` 的理由欄 |
| 原編碼錯誤 | 修正該列，重新執行受影響的層 |
| 判準本身含糊 | 修正判準表或本 skill 的說明，重新判讀受影響的全部列 |

### 審核狀態

subagent 與主 session 是同一類模型，抽查不算獨立複評，審核狀態維持「未經獨立複評」。只有維護者依同一判準複評且結果一致時，才改為「獨立複評通過」。
