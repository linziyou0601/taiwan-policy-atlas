# 抓取

抓取階段登錄一場選舉用到的來源，把原始檔下載到本機快取並核對 sha256，寫出列有每個來源與檔案雜湊的 manifest。收錄一場選舉從這個階段開始，已收錄的選舉新增公報時也回到這個階段。

<br>

## 輸入

| 輸入 | 位置 | 說明 |
|---|---|---|
| 來源登錄 | `data/sources.yaml` | 手寫。每個來源的代碼、adapter、網址、sha256 與授權，各鍵的意思寫在檔內的註解 |
| 選舉定義 | `data/10-fetch/{選舉代碼}/election.yaml` | 手寫。選舉的職位、選區類型、名冊來源與公報文件，各鍵的意思寫在檔內的註解 |
| 原始檔 | 來源登錄的網址 | 下載後存在 `.cache/sources/{來源代碼}/` |

<br>

## 步驟

新增一場選舉時從第 1 步開始，已收錄的選舉新增公報時從第 2 步開始：

1. 建立 `data/10-fetch/{選舉代碼}/election.yaml`：複製另一場選舉的定義改寫，名冊的來源與目錄依中選會選舉資料庫。
2. 公報不在已登錄的來源時，在 `data/sources.yaml` 登錄一筆。來源是單一封存檔時寫下載網址、檔名與 sha256。來源是網站目錄時只寫網址，每份文件的路徑與 sha256 寫在選舉定義的 `documents`。
3. 公報在中選會地方選舉公報網站時，先列出並下載這一類的公報。清單寫在 `.cache/pipeline/`，[抽取](extract.md) 依它把公報對到選區：

   ```bash
   npm run pipeline -- fetch list --year <民國年> --folders <類別>...
   ```

4. 下載選舉定義登錄的來源並寫出 manifest，`--offline` 只用已下載的原始檔：

   ```bash
   npm run pipeline -- fetch run --election <選舉代碼>
   ```

完成判準如下：

| 條件 | 證據 |
|---|---|
| 選舉定義引用的每個來源與每份文件都已下載並核對 | `fetch run` 的結束代碼是 0 |
| manifest 列出每個來源與每份文件的 sha256 | `data/10-fetch/{選舉代碼}/manifest.json` |

<br>

## 判讀規則

### 來源

來源限每位候選人都能發言、能取得本人原文、可以保存快照的管道：選舉公報、本人官網與粉專的快照、政見發表會與辯論的逐字稿。候選人之間因此站在同一個基準上比較。新聞只用來找線索，引用一律回到本人的來源。議會的質詢與提案紀錄只有現任者能發言，已完成的政績也只有現任者有，兩者都略過。

### 來源缺漏

來源沒有某個選區的公報，或公報的檔案損壞而無法解析時，這個選區的參選者沒有段落。缺漏的選區、號次與原因寫在選舉定義 `documents` 上方的註解。

<br>

## 核對

| 核對範圍 | 失敗條件 |
|---|---|
| 來源登錄 | 來源代碼重複，選舉定義引用了沒有登錄的來源，來源的 adapter 沒有登錄 |
| 原始檔 | 下載失敗，或檔案的 sha256 與登錄的不同 |
| `--offline` | 快取沒有這個來源的檔案 |

<br>

## 產物

| 產物 | 位置 |
|---|---|
| manifest：每個來源的 adapter、檔案位置、sha256 與授權，網站目錄的來源另列每份文件 | `data/10-fetch/{選舉代碼}/manifest.json` |
