# 抽取

抽取階段匯入名冊，把每位參選者的公報政見逐字轉錄成段落，登錄名冊以外會洩漏身分的用語，並以 OCR 核對影像型政見的轉錄。之後每個階段引用的原文都來自這個階段的轉錄稿。公報影像的文字辨識使用 Apple Vision，這個階段在 macOS 執行。

<br>

## 輸入

| 輸入 | 位置 | 說明 |
|---|---|---|
| 抓取階段的 manifest 與原始檔 | `data/10-fetch/{選舉代碼}/manifest.json`、`.cache/sources/` | 名冊與公報 |
| 選舉定義的 `documents` | `data/10-fetch/{選舉代碼}/election.yaml` | 每份公報的路徑、sha256、標題與政見影像 |
| 選區表與名冊表 | `data/20-extract/{選舉代碼}/scopes.tsv`、`roster.tsv` | 手寫，選舉定義的 `roster` 寫 `tables: true` 時取代名冊來源，見 [名冊表](#名冊表) |
| 轉錄稿 | `data/20-extract/{選舉代碼}/transcripts/{選區代碼}-{號次}.txt` | 手寫，每段一個檔 |
| 段落表 | `data/20-extract/{選舉代碼}/transcripts.tsv` | 手寫，每段一列 |
| 遮蔽詞表 | `data/20-extract/{選舉代碼}/aliases.tsv` | 手寫，每個用語一列 |
| 造字表 | `scripts/pipeline/tables/roster-characters.tsv` | 手寫，名冊姓名中的造字換成什麼字 |

<br>

## 步驟

工具的中間檔都寫在 `.cache/pipeline/{選舉代碼}/`，轉錄的草稿寫在 repo 之外的暫存目錄，核對後才寫入 repo：

1. 準備名冊。名冊來自來源的選舉，匯入名冊寫在 `data/20-extract/{選舉代碼}/roster.json`。中選會的名冊以私用區的造字代替罕用字，名冊含造字表沒有的造字時這一步停止並列出參選者，依 [造字表](#造字表) 登錄後重新執行。選舉定義的 `roster` 寫 `tables: true` 時，改由上一屆的名冊寫出 [名冊表](#名冊表) 的選區表，選區有變動時對照公報改表，參選者在轉錄時補上：

   ```bash
   npm run pipeline -- extract run --election <選舉代碼>
   npm run pipeline -- extract scopes --election <選舉代碼> --from <上一屆的選舉代碼>
   ```

2. 公報由 `fetch list` 取得時，寫出每個選區的轉錄素材：名冊、可能用到的公報，以及每份公報各頁的文字層與嵌入影像的位置。公報依路徑的類別、縣市與鄉鎮或選舉區編號對到選區，素材沒有公報的選區，從公報清單找出它的公報，以 `--assign` 指定後重新執行：

   ```bash
   npm run pipeline -- extract units --election <選舉代碼> --source <來源代碼> --folders <類別>...
   npm run pipeline -- extract units --election <選舉代碼> --source <來源代碼> --folders <類別>... --scopes <選區> --assign <選區> <路徑>
   ```

3. 把公報頁面渲染成 PNG 檢視，整頁渲染時一併寫出該頁的文字層，依號次與姓名找出每位參選者的政見欄。轉錄時以 `--clip` 只渲染政見欄，並提高 `--scale` 到字高 30 像素以上。渲染圖寬於 1000 像素時依欄位分成數個範圍，相鄰兩個範圍至少重疊一行：

   ```bash
   npm run pipeline -- extract render <PDF> --out <目錄>
   ```

4. 依 [轉錄](#轉錄) 逐字轉錄每位參選者的政見，格式見 [複評與抽查的草稿格式](review-protocol.md#草稿格式)。名冊表的選舉，同時依公報把參選者寫成名冊表的草稿。
5. 寫入段落。`collect` 讀各選區的轉錄輸出，把用到的公報與政見影像依 sha256 登錄到選舉定義的 `documents`，再寫入轉錄稿與段落表。公報已登錄在選舉定義時，改用 `transcripts` 寫入段落表格式的草稿。兩支工具都把名冊表的草稿併入名冊表：

   ```bash
   npm run pipeline -- extract collect --election <選舉代碼> --office <字尾>=<職稱> <選區輸出目錄>...
   npm run pipeline -- extract transcripts --election <選舉代碼> <草稿目錄>...
   ```

6. 依 [遮蔽詞](#遮蔽詞) 登錄 `aliases.tsv`。工具列出兩張表：候選的用語，以及已登錄而在其他參選者轉錄稿出現的用語：

   ```bash
   npm run pipeline -- extract aliases --election <選舉代碼>
   ```

7. 登錄了新的公報時先執行 [抓取](fetch.md) 的 `fetch run`，再執行這個階段。接著列出還要判斷的影像段落，依 [OCR 比對](#ocr-比對) 逐段處理：

   ```bash
   npm run pipeline -- extract run --election <選舉代碼>
   npm run pipeline -- extract ocr --election <選舉代碼>
   ```

完成判準如下：

| 條件 | 證據 |
|---|---|
| 選區表的每個選區都有參選者 | `roster.json` |
| 範圍內每位參選者都有段落，或列在選舉定義的 [來源缺漏](fetch.md#來源缺漏) | `transcripts.tsv`、名冊的人數與選舉定義的註解 |
| 這個階段的核對通過 | `extract run` 的結束代碼是 0 |
| 影像段落都已比對 | `extract ocr` 每一列的已記錄欄都是「是」 |

## 判讀規則

### 轉錄

政見的來源依頁面判斷：

- 頁面有可用的文字層時，以文字層為起點，對照渲染圖核對每一行。文字層的繪製順序可能與版面不同，政見屬於哪個號次依渲染圖上的位置判斷。
- 文字層是 OCR 產生、幾乎空白、字型對應錯誤而缺字，或以擴充字元替代正字時，視為沒有可用的文字層，照渲染圖轉錄。
- 政見欄整個是一張嵌入影像時，記下影像代碼 `p{頁碼}-{嵌入順序}`。同一位置疊了尺寸相同、像素相同的數張影像時取嵌入順序最前的一張。相片、QR code、黨徽與裝飾圖略過。

逐字轉錄的寫法：

- 依版面的閱讀順序轉錄，政見欄分成數欄時依欄序。標題、條目與原文的段落各占一行，因欄寬而折到下一行的句子與縮排的續行接回原來那一行。條目標題下另起的說明是另一行，條目連續排版時依編號每條各占一行。表格每列寫成一行，格與格之間以一個半形空格分隔。
- 編號、項目符號、標點與簡繁照原文，圖形的項目符號照形狀寫成對應的字元。
- 有可用的文字層時依文字層的字碼照錄，異體字照錄。沒有可用的文字層時照圖上的字形，錯字也照錄。
- 字距拉開的空白與折行處的空白刪除，原文以空白代替標點分隔短語時寫一個半形空格。文字層中同一個字重複繪製成粗體時只保留一份。
- 只轉錄候選人寫在政見欄的內容，號次、姓名、學經歷、公報印製的頁尾宣導、選票樣張與廣告略過。
- 政見欄內印給讀者讀的文字照錄，QR code、相片、圖形與黨徽本身，以及拍進相片裡的字、畫在插圖裡的字與手寫簽名略過。政見欄空白或只有圖形時寫空檔。
- 辨識不出的字以〔?〕標示。
- 兩位參選者的政見全文相同時，後一位的段落指向前一位的轉錄檔。

### 段落表

| 欄 | 寫法 |
|---|---|
| 代碼 | `{選區代碼}-{號次}-p{序號}`。政見欄分成各自完整的數塊時每塊登錄一段，序號依版面順序，第二段起的轉錄檔名加上 `-p{序號}` |
| 參選者 | 名冊的對象代碼 |
| 文件 | 選舉定義 `documents` 的文件代碼 |
| 影像 | 這一段整個是一張影像時寫 `{文件代碼}-p{頁碼}-{嵌入順序}`，其餘寫 - |
| 頁 | 政見欄所在的頁碼 |
| 轉錄檔 | `transcripts/` 下的檔名 |
| 理由 | 政見的來源、閱讀順序、照錄的錯字與異體字、略過的圖形，以及 OCR 的比對判斷 |

### 遮蔽詞

名冊上的姓名、搭檔與黨名由網站在翻牌前遮蔽。`aliases.tsv` 登錄名冊以外讓讀者認得出參選人或推知其政治關係的用語。遮蔽是全場共用的子字串替換，登錄的詞出現在其他參選者的轉錄稿，而且在那裡是一般用語時，改登錄較長、全場唯一的寫法。類別依 `mask-categories.tsv`：

| 類別 | 登錄的用語 |
|---|---|
| 姓名 | 名冊姓名的其他寫法 |
| 暱稱 | 暱稱、縮寫與以名字自稱的寫法 |
| 黨名 | 政黨的簡稱與外文名稱 |
| 識別字 | 其餘讓讀者認得出參選人或推知其政治關係的用語 |

### OCR 比對

`extract run` 為每個影像段落記錄轉錄稿與 OCR 的字元重合度，以及轉錄稿中找不到的 OCR 行。逐行放大影像對照沒有對上的行：OCR 誤讀時保留轉錄稿，轉錄漏字或錯字時修正轉錄稿。重合度低於 0.95 時整段重新比對。判斷的結果寫進段落表的理由欄並寫出「OCR」兩字，`extract ocr` 依它把這一段的已記錄欄標成「是」。

### 名冊表

選舉資料庫在投票之後才收錄一場選舉。選前收錄時，選舉定義的 `roster` 寫 `tables: true`，名冊依公報手寫在兩張表。選舉資料庫收錄之後，`roster` 改回名冊來源重新執行，逐筆核對兩份名冊的差異。

| 表 | 欄 | 寫法 |
|---|---|---|
| `scopes.tsv` | 代碼 | 選區代碼，與名冊來源的 adapter 依行政代碼組成的代碼相同 |
| `scopes.tsv` | 名稱 | 選區的顯示名稱，與名冊來源的寫法相同 |
| `scopes.tsv` | 縣市 | 縣市的行政代碼，全國性選舉寫 - |
| `scopes.tsv` | 涵蓋 | 區域選區所含的鄉鎮市區，鄉鎮市民代表選區所含的村里，其他選區類型寫 - |
| `scopes.tsv` | 鄉鎮市區 | 選區所在或涵蓋的鄉鎮市區，全國與縣市選區寫 - |
| `roster.tsv` | 代碼 | `{選區代碼}-{號次}` |
| `roster.tsv` | 姓名 | 公報印的姓名 |
| `roster.tsv` | 搭檔 | 正副組合的副手姓名，其餘寫 - |
| `roster.tsv` | 推薦政黨 | 政黨的全名，沒有政黨推薦時寫「無黨籍及未經政黨推薦」，與名冊來源的寫法相同 |
| `roster.tsv` | 現任 | 是或否。公報發布時擔任這個職位的參選人寫是，依上一屆的當選人與之後的補選判斷 |
| `roster.tsv` | 理由 | 抄錄的公報與頁碼，以及現任的判斷依據 |

### 造字表

造字表的代碼是名冊目錄的西元年與造字的碼位，寫成 `2022-E011`，同一個碼位在不同年度代表不同的字。字寫公報姓名欄印的用字，公報印異體字時寫網站與轉錄稿用的正字，說明寫依據的公報。

<br>

## 核對

| 核對範圍 | 失敗條件 |
|---|---|
| 名冊 | 同選區的號次重複，姓名含造字表沒有的造字 |
| 名冊表 | 參選者的選區不在選區表，號次不是整數，現任不是是或否 |
| 文件 | 選舉定義列出的影像不在 PDF 中，PDF 無法解析 |
| 段落表 | 參選者不在名冊，文件或影像沒有登錄在選舉定義，轉錄檔不存在，方法或審核狀態沒有登錄 |
| 遮蔽詞表 | 參選者不在名冊，類別沒有登錄在 `mask-categories.tsv` |
