# 發布

發布階段把前面各階段的產物合成網站讀取的資料集，重寫題組索引，並以區辨力報告檢視題組能不能分出候選人。一場選舉在這個階段結案。

<br>

## 輸入

| 輸入 | 位置 | 說明 |
|---|---|---|
| 評分階段的產物 | `data/50-score/{選舉代碼}/score.json` | 連同轉交的抽取、主張與配題階段產物 |
| 地圖的產物 | `data/geo/map.json`、`data/geo/villages/` | 各縣市的村里代碼與名稱、村里異動、名稱對照與地圖版本，見 [地圖](geo.md) |
| 選區涵蓋表 | `data/60-publish/{選舉代碼}/scope-areas.tsv` | 手寫。名冊只寫到鄉鎮而選區切開鄉鎮時，完整定義選區涵蓋的鄉鎮市區與村里 |
| 來源類型 | `config/tables/source-types.tsv` | 各類來源的權重與是否作為立場證據 |
| 資料集的格式 | `config/app/settings.json` 的 `formats` | 網站與管線共用的格式戳記 |

<br>

## 步驟

結案依序執行，抽查發現系統性的問題時修正判準或詞表，從受影響的階段重新執行：

1. 寫出資料集並更新索引。重新執行整場選舉時以 `run` 從抓取階段依序執行：

   ```bash
   npm run pipeline -- publish run --election <選舉代碼>
   npm run pipeline -- run --election <選舉代碼> --offline
   ```

2. 選區的涵蓋沒有通過時，訊息一次列出全部問題，依問題修正後重新執行：
   - 名稱只是用字不同時，在 [地圖設定](geo.md#輸入) 的 `name_equivalents` 登錄對照。
   - 同一個村里屬於兩個選區時，依選舉區劃分的公告，在選區涵蓋表寫出這幾個選區的全部涵蓋。
   - 名冊的村里在地圖上找不到時，依村里調整的公告在 [地圖的村里異動表](geo.md#判讀規則) 登錄，重新執行地圖階段。
3. 依 [複評與抽查](review-protocol.md#抽查) 的範圍抽查，逐筆處理不一致。
4. 寫出區辨力報告並依 [區辨力報告](#區辨力報告) 判讀，省略選舉代碼時涵蓋索引的全部選舉：

   ```bash
   npm run pipeline -- publish report <選舉代碼>...
   ```

5. 以 `npm start` 重新建置並開啟網站，操作一個選區，從作答到結果、分享與重播。
6. 執行 [CONTRIBUTING 的本機驗證](../../CONTRIBUTING.md#本機驗證)。

完成判準如下：

| 條件 | 證據 |
|---|---|
| 資料集與索引已寫出 | `publish run` 的結束代碼是 0，`data/60-publish/index.json` 有這場選舉 |
| 抽查範圍的每一項都已完成，每筆不一致都已處理 | 抽查的紀錄 |
| 區辨力報告的每個項目都已判讀 | 報告與判讀的結論 |
| 網站能以這場選舉作答並重播 | 瀏覽器操作的結果 |

<br>

## 判讀規則

### 選區涵蓋

網站依每個選區涵蓋的村里代碼合併村里，畫出選區。選區的涵蓋依序取下列第一個有內容的來源：

| 來源 | 涵蓋 |
|---|---|
| 選區涵蓋表的列 | 每列是一個鄉鎮市區，村里寫 - 時是這個鄉鎮市區的全部村里，否則是列出的村里 |
| 名冊的 areas | 每格是鄉鎮市區或村里，一格以頓號寫多個村里時拆開。先當鄉鎮市區找，找不到再到選區所在的鄉鎮內找村里 |
| 名冊的 towns | 這些鄉鎮市區的全部村里 |
| 都沒有 | 這個縣市的全部村里 |

未編定村里沒有選民，不屬於任何選區。名冊與地圖的名稱依地圖設定的 `name_equivalents` 比對。選舉年度早於村里異動實施日期的年度時，名冊寫的是異動前的村里，先換成異動後的全部村里再比對。

選區涵蓋表的寫法：

| 欄 | 寫法 |
|---|---|
| 代碼 | `{選區代碼}-{序號}`，序號從 1 起 |
| 選區 | 名冊的選區代碼，含選舉代碼的前綴 |
| 鄉鎮市區 | 地圖上的鄉鎮市區名稱 |
| 村里 | 地圖上的村里名稱，以頓號分隔；整個鄉鎮市區寫 - |

### 區辨力報告

報告以網站的資料層與計分層讀取已發布的選舉，只計有兩位以上參選人的選區。報告的各個項目：

| 項目 | 意思 | 要回頭檢查的情形 |
|---|---|---|
| 共識題比例 | 表態的候選人方向全部相同的題目占比，共識題預設不計入排序 | 比例高的選區，題目只問到大家都同意的方向，回到 [配題的出題](match.md#出題) 找做法不同之處出子題 |
| 第一、二名同分與差距很小的比例 | 隨機作答下排名分不出高下的比例 | 比例高時，選區的題數或表態太少 |
| 全部候選人都資料不足 | 隨機作答下沒有人達到可比較題數的比例 | 選區的政見太少，屬於來源的限制 |
| 各第 1 層議題的立場分布 | 題次、只有一位表態、有支持也有反對的比例，以及各立場等級的比例 | 只有一位表態的題目多時，這個議題的題目分不出候選人 |

## 核對

| 核對範圍 | 失敗條件 |
|---|---|
| 轉交 | 前面任一個階段的檔案在產物寫出之後修改過 |
| 選區涵蓋 | 地圖還沒轉出，選區的縣市代碼、鄉鎮市區或村里對不到地圖的村里，同一個村里屬於兩個選區，涵蓋表寫了名冊沒有的選區 |
| 地圖版本 | 資料集記的地圖版本與目前的地圖不同，由 `npm test` 核對 |
| 資料集 | 內容不符 `formats` 宣告的格式 |

<br>

## 產物

選舉的資料集分成總檔與選區檔。段落、OCR、主張、配題與具體度依所屬選區寫入選區檔，網站選定選區後才讀取，總檔的 manifest 以 `scope_files` 列出各選區檔，總檔的每個選區以 `villages` 列出涵蓋的村里代碼，`map` 記解析時的地圖版本。資料版本是總檔與選區檔合起來的完整內容的 sha256 前 12 碼，分享連結以它判斷能否精確重播。題組移除之後以 `npm run pipeline -- publish index` 單獨重寫索引。各產物的位置：

| 產物 | 位置 |
|---|---|
| 資料集總檔 | `data/60-publish/{選舉代碼}/dataset.json` |
| 選區檔 | `data/60-publish/{選舉代碼}/scopes/{選區代碼}.json` |
| 題組索引：`elections` 與 `topics` 分列選舉與主題測驗，每筆帶 `kind`、資料集路徑與 manifest | `data/60-publish/index.json` |
| 區辨力報告 | 標準輸出，Markdown |
