# 配題

配題階段把每則主張分配到分類樹的面向，為有主張的面向出題，並判讀每則主張對題目的立場。題目來自這場選舉候選人的主張，每題至少一筆配題證據。

<br>

## 輸入

| 輸入 | 位置 | 說明 |
|---|---|---|
| 主張階段的產物 | `data/30-claims/{選舉代碼}/claims.json` | 主張與受控欄位 |
| 配題表 | `data/40-match/{選舉代碼}/mappings.tsv` | 手寫，一則主張分配到一個面向是一列 |
| 題目表 | `data/40-match/{選舉代碼}/questions.tsv` | 手寫，每道題目一列 |
| 軸對應表 | `data/40-match/{選舉代碼}/question-axes.tsv` | 手寫，一道題目對一條軸是一列 |
| 分類樹、立場判準、作答量尺、意識形態軸 | `config/tables/` 的 `taxonomy-issues.tsv`、`rubric-stance.tsv`、`scale-answers.tsv`、`axis-ideology.tsv` | 分類樹的增修見 [詞表與分類樹](vocabulary-policy.md) |

<br>

## 步驟

配題列在 [主張](claims.md) 階段連同主張一起寫入，這時題目、題目版本、立場與證據都是 -，這個階段補齊：

1. 依 [分配](#分配) 檢查每則主張的配題列。改寫面向的配題列以 [複評與抽查](review-protocol.md#草稿格式) 的草稿寫入，同代碼的列覆寫。

2. 依 [出題](#出題) 寫題目表。面向與命題和其他場次的題目相同時沿用那一題，工具連同軸對應與中立性審查一起複製，複製後依 [沿用](#沿用) 改寫兩處：

   ```bash
   npm run pipeline -- match reuse --election <選舉代碼> --from <來源選舉代碼> <題目代碼>...
   ```

3. 依 [立場](#立場) 填配題列的題目、題目版本、立場、證據與理由，再替只分配到子題的主張補上母題的配題列。子題判為反對的列由工具列出代碼，依 [出題](#出題) 的母題與子題判斷後手寫：

   ```bash
   npm run pipeline -- match parents --election <選舉代碼>
   ```

4. 依 [意識形態軸](#意識形態軸) 寫軸對應表，中立性審查見 [評分](score.md)。
5. 題目要改代碼時以工具修改，題目表、軸對應表、中立性表與配題表一起改：

   ```bash
   npm run pipeline -- match rename --election <選舉代碼> --old <題目代碼> --new <題目代碼>
   ```

6. 執行這個階段的核對，再列出同一個題目代碼在各場選舉寫法不同的地方。同一個代碼是同一個命題，寫法不同時判斷是筆誤或該另取代碼：

   ```bash
   npm run pipeline -- match run --election <選舉代碼>
   npm run pipeline -- match stems
   ```

完成判準如下：

| 條件 | 證據 |
|---|---|
| 每個有主張的面向都有題目，或配題列的理由寫明不出題的原因 | `mappings.tsv` 題目欄是 - 的列 |
| 這個階段的核對通過 | `match run` 的結束代碼是 0 |
| 同一個題目代碼在各場選舉是同一個命題 | `match stems` 列出的每一筆都已判斷 |

<br>

## 判讀規則

### 分配

每則主張至少一列配題，分配到分類樹中說明涵蓋它的最深節點，同一則主張的分配合計為 1。主張只涉及一個面向時分配寫 1，涉及多個面向時依原文的重點分配。分類樹沒有適合的節點時依 [詞表與分類樹的增修判準](vocabulary-policy.md#增修判準) 處理。配題列的代碼寫 `{主張代碼}-m{序號}`。

### 出題

題目的命題是政策方向，沒有讀過政見的人也能依自己的立場作答，也要能分出候選人的立場。單一地點的工程與選址併入所屬面向的題目，立場依那一題判讀。全場只有一兩則同向主張的命題併入較上層的題目。說明的現況寫成「{年} 年選舉時」的狀態，只寫投票日前的一手來源能查證的事實。題目表的各欄：

| 欄 | 寫法 |
|---|---|
| 代碼 | `q.{面向代碼}`，子題沿用母題面向時加上一段後綴。同一個代碼在各場選舉是同一個命題，命題不同時另取代碼 |
| 面向 | 分類樹的節點，與配題列的面向相同 |
| 母題 | 根題寫 -，子題寫母題的代碼。根題在網站上稱主問題，子題稱追問題 |
| 題幹 | 一句話，以「政府應」「某某應」陳述，句末使用句號 |
| 說明 | 解釋題幹的專有名詞，提到現況時以投票日為準 |
| 顯示條件 | 根題寫 -，子題寫「中立、同意、非常同意」，母題回答這三種時才追問 |
| 預算份額 | 根題寫 1，子題寫 0.5，網站依實際出現的題目正規化 |
| 適用範圍 | 全部選區寫「全部」，只適用部分選區時寫選區代碼 |
| 版本 | 第一次發行前都是 1。發行後題幹、說明、面向或顯示條件修改時加 1，配題依新版重新核對 |

母題與子題的寫法：

1. 候選人方向相同、做法或金額不同的面向寫一道母題與數道子題。母題採用共同的方向，子題詢問各自的做法。
2. 子題的金額或年份採用某位候選人原文的數字，其他候選人的數額依 `rubric-stance.tsv` 判斷立場。
3. 沒有提出數字或沒有提到子題做法的候選人記為未知，子題沒有他的配題列。
4. 主張只分配到子題時，同一則主張再加一列母題的配題，兩列的分配各半。子題判為反對、方向與母題相同時，母題判為支持。

### 沿用

沿用的題目照抄題幹、說明、顯示條件、預算份額、版本、軸對應與中立性審查，再改兩處：說明的現況改寫為這場選舉的年份並依這場的投票日重新查證，中立性「不洩漏身分」的理由寫這場選舉的參選者。適用範圍寫了選區代碼的題目，選區改成這場選舉的選區。

### 立場

立場寫 `rubric-stance.tsv` 的名稱，依該表的判準判斷。證據寫主張原文中支持這個判讀的一段，理由寫判讀的推論。主張與題目的方向無關或無法判斷，或配題的面向是第 1 層議題節點時，題目寫 -，這一列只計入議題分布。常見的原文寫法依下表判讀：

| 原文 | 立場 |
|---|---|
| 寫出本題命題，或寫出達成命題的具體做法 | 強烈支持 |
| 列出要新設的設施名稱 | 強烈支持 |
| 寫出具名設施的整修、拓寬工程，題目問的是增加投入或建設 | 強烈支持 |
| 只寫方向或目標 | 支持 |
| 改善、維修或養護既有設施，題目問的是增設或加強 | 支持 |
| 只寫監督、關注或評估某項政策 | 支持 |
| 持續推動、持續建設或落實一項政策，表示還會再增加 | 依有沒有寫出做法判支持或強烈支持 |
| 督促、要求政府推動某項政策 | 依那項政策判讀 |
| 續辦既有的活動、延續既有的給付或方案、維持原有水準，題目問的是增加或擴大 | 中立 |
| 反對在某一處興建某項設施，題目問的是增設這類設施 | 反對 |
| 只要求檢討，或附條件反對而命題本身沒有反對 | 題目寫 - |
| 只寫審查、監督預算 | 題目寫 - |

### 意識形態軸

每題對 `axis-ideology.tsv` 有關的軸各寫一列，代碼寫 `{題目代碼}-{軸代碼}`。增加政府支出的題目對財政緊縮軸寫 -1、0.5，擴大公共給付或照顧的題目對擴大福利國家軸寫 1、1。兩岸題目分清統獨立場與兩岸交流：前者詢問最終關係，後者詢問往來的多寡。方向不確定的題目沒有軸對應，維持兩岸現狀的題目屬於這一種。軸對應表的各欄：

| 欄 | 寫法 |
|---|---|
| 方向 | 同意時往正極寫 1，往負極寫 -1 |
| 權重 | 題目直接表達這個軸的取向寫 1，只是間接相關寫 0.5 |
| 理由 | 「同意表示…，往某一極」，權重 0.5 時說明為何只是間接相關 |

## 核對

| 核對範圍 | 失敗條件 |
|---|---|
| 配題 | 面向不在分類樹，一則主張的分配合計不是 1，證據不在主張原文，立場與判準代碼不在 `rubric-stance.tsv` 的同一列，題目版本過期 |
| 題目 | 題目沒有任何配題證據，母題不存在或母題關係成環，顯示條件不是作答量尺的名稱 |
| 軸對應 | 題目或軸沒有登錄，方向不是 1 或 -1，權重不大於 0 |
| 方法與審核狀態 | 寫了沒有登錄的名稱 |
