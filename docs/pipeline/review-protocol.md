# 複評與抽查

轉錄、編碼與出題的量大時怎麼分給多個工作者、草稿用什麼格式交回、交回後怎麼核對，以及一場選舉結案前要抽查什麼。主責者把可以分開驗收的工作交給協作者，結果一律由主責者核對後才寫入 repo，主責者對最後的資料負責。適用於收錄一場選舉時的分工，以及 [發布](publish.md) 階段的抽查。

<br>

## 分批與派工

批次依原文的量切：每個協作者都要先讀一遍規則，一批的內容要夠多，這段成本才攤得開。轉錄的素材由 [抽取](extract.md) 的 `extract units` 產生，轉錄與編碼的範圍都由 [主張](claims.md) 的 `claims progress` 決定：它列出每個群組的名冊人數、已轉錄的人數、有主張的人數與還沒有主張的字數。派工依下列規則：

- 轉錄每批約 60 位參選人，影像型政見多時減少。編碼以同一個縣市為一批，每批的轉錄稿約 2 萬字，同一個地區的用語相近，判法容易一致。
- PDF 的解析與渲染占用大量 CPU，同一台機器同時只處理一份 PDF。
- 每批一個輸出目錄，放在 repo 之外的暫存目錄。協作者只讀取 repo、只寫自己的輸出目錄，同時進行的批次因此互不覆寫。
- 派工訊息寫明要讀的文件與章節、範圍、輸出目錄、[草稿格式](#草稿格式)，並要求回報只列出不一致與沒有把握的地方。
- 數份草稿同時為同一場選舉寫配題列時，各份的代碼序號錯開。
- 協作者中斷時請同一個協作者接續，並先檢查輸出目錄已完成的部分。它保有已讀的規則與已完成的判讀，換一個協作者要從頭再讀一次。

工作依判斷的量選擇模型：

| 工作 | 模型 | 理由 |
|---|---|---|
| 公報逐字轉錄 | 能力最高的一級 | 轉錄稿是之後每個階段的原文 |
| 主張、欄位、配題與具體度的草稿 | 能力最高的一級 | 拆分主張與配題的判斷量最高，重新製作的成本高 |
| 出題、立場、軸對應與中立性的草稿 | 能力最高的一級 | 題目決定整場選舉的比較基準 |
| 抽查立場、分配與具體度的判讀 | 中間的一級 | 要閱讀判準並說明理由 |
| 轉錄稿對照渲染圖的逐字比對 | 中間的一級 | 要放大頁面辨識小字與異體字 |
| 原文欄與轉錄稿的逐字比對 | 最輕量的一級 | 機械比對，判斷量低 |

完成判準如下：

| 條件 | 證據 |
|---|---|
| 範圍內的每位參選者都屬於一個批次 | 批次的清單與名冊 |
| 每個批次有自己的輸出目錄 | 派工訊息 |

## 草稿格式

草稿是 TSV，表頭與 repo 對應的手寫表相同，空值寫 -，多值以頓號分隔，列的順序由寫入的工具排定。各種工作的輸出：

| 工作 | 輸出目錄的內容 | 寫入的工具 |
|---|---|---|
| 轉錄 | 每個選區一個以選區代碼命名的目錄，放 `{選區代碼}-{號次}.txt` 與說明表 `notes.tsv`。說明表的表頭是選區、號次、文件、頁、影像、說明：文件寫素材的公報目錄名，影像寫 `p{頁碼}-{嵌入順序}` 或 -，參選者不在任何一份公報時文件與頁寫 -，說明寫段落表理由欄要記的內容或 [來源缺漏](fetch.md#來源缺漏) 的原因。選舉定義的 `roster` 寫 `tables: true` 時另有 [名冊表](extract.md#名冊表) `roster.tsv` | `extract collect` |
| 轉錄，公報已登錄在選舉定義 | `transcripts.tsv` 與轉錄檔。選舉定義的 `roster` 寫 `tables: true` 時另有 [名冊表](extract.md#名冊表) `roster.tsv` | `extract transcripts` |
| 主張、欄位、配題與具體度 | 每位參選者一個 `{選區代碼}-{號次}/`，放 `claims.tsv`、`mappings.tsv`、`specificity.tsv`，原文起訖與題目各欄寫 -。新詞與新節點寫在最上層的 `vocab-new.tsv`、`taxonomy-new.tsv`，狀態寫待審，裁定後由主責者加入設定表 | `claims merge` |
| 出題 | `questions.tsv`、`mappings.tsv`、`question-axes.tsv`、`neutrality.tsv`，配題涵蓋範圍內的每一列 | `claims merge` |

<br>

## 核對與寫入

草稿交回後由主責者核對：逐項處理協作者回報沒有把握的判讀，與既有資料的寫法不一致時依規則與先例修正草稿，再以上表的工具寫入 repo 並執行那個階段的 `run`。寫入的工具在下列情況停止並列出代碼，草稿修正後重新寫入：

| 寫入 | 停止的情況 |
|---|---|
| 轉錄 | 說明表的表頭不符，名冊沒有這個號次，缺轉錄檔，公報的代碼重複 |
| 編碼與出題 | 草稿的表頭不符，題目、軸對應或中立性的同一個代碼在 repo 已有不同的內容 |

完成判準如下：

| 條件 | 證據 |
|---|---|
| 協作者回報的每一筆都已處理 | 回報與草稿的修正 |
| 草稿已寫入，階段的核對通過 | 那個階段 `run` 的結束代碼是 0 |

<br>

## 抽查

每場選舉結案前至少抽查下列範圍：

1. 每位候選人五則主張回到公報頁面，逐字比對原文欄。
2. 抽取階段沒有 OCR 比對的段落全部重新比對。公報沒有可用的文字層、政見欄也不是嵌入影像時，轉錄稿只經過轉錄者一次讀圖，由另一個協作者對照渲染圖逐字比對。
3. 每個有配題的面向一筆配題，重新檢視立場與理由是否符合 `rubric-stance.tsv`。
4. 全部的反對、強烈反對立場，以及全部子題的配題。
5. 每位候選人五則主張的每條具體度評分，對照 `rubric-specificity.tsv` 的級距描述。
6. 全部現任政府計畫標為是的主張，確認它不是已完成的政績。

抽查回報的每筆不一致，主責者逐筆回到原文或影像判斷：

| 判斷 | 處理 |
|---|---|
| 原編碼正確 | 保留原編碼，判斷的依據補到該列的理由欄 |
| 原編碼錯誤 | 修正該列，從受影響的階段重新執行 |
| 判準本身含糊 | 修正判準表或那個階段文件的規則，重新判讀受影響的全部列 |

完成判準如下：

| 條件 | 證據 |
|---|---|
| 六個範圍都已抽查 | 抽查的紀錄 |
| 每筆不一致都已判斷並處理 | 每筆的判斷與修正後各階段 `run` 的結束代碼 |

<br>

## 審核狀態

主責者與協作者是同一類模型時，抽查不算獨立複評，審核狀態維持「未經獨立複評」。維護者依同一條判準複評而且結果一致時，才改為「獨立複評通過」。
