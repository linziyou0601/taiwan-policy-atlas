# 主張

主張階段把每段轉錄稿拆成主張，並把主張的內容填進受控欄位。一則主張是一個可以單獨同意或反對的政策，配題、立場與具體度都以主張為單位。

<br>

## 輸入

| 輸入 | 位置 | 說明 |
|---|---|---|
| 抽取階段的產物 | `data/20-extract/{選舉代碼}/` | 名冊、段落與轉錄稿 |
| 主張表 | `data/30-claims/{選舉代碼}/claims.tsv` | 手寫，每則主張一列 |
| 詞表 | `config/tables/vocab-terms.tsv` | 受控欄位可以寫的詞，增修見 [詞表與分類樹](vocabulary-policy.md) |

<br>

## 步驟

主張的草稿同時包含這則主張的配題列與具體度評分，三者在這個階段一起寫入，規則分別見 [配題](match.md) 與 [評分](score.md)：

1. 列出各群組的名冊人數、已轉錄人數、有主張的人數與還沒有主張的人的轉錄稿字數，依字數決定這一批編碼的範圍。有主張的人數只算主張表有列的人，編碼後沒有可建立主張的人要對照編碼紀錄：

   ```bash
   npm run pipeline -- claims progress --election <選舉代碼>
   ```

2. 依 [拆分](#拆分) 與 [欄位](#欄位) 寫出每位參選者的主張，草稿的格式見 [複評與抽查的草稿格式](review-protocol.md#草稿格式)。
3. 詞表沒有適合的詞時，依 [詞表與分類樹的增修判準](vocabulary-policy.md#增修判準) 判斷沿用、改填別的欄位或新增。新詞以待審的狀態登錄，裁定後才能通過這個階段。
4. 把核對過的草稿寫入各階段的手寫表。草稿涵蓋的參選者，原有的主張連同配題與具體度整批換成草稿的內容：

   ```bash
   npm run pipeline -- claims merge --election <選舉代碼> <草稿目錄>...
   ```

5. 填入原文的起訖，依原文的順序重新編號，再執行這個階段的核對。原文在段落中出現零次或多次時 `offsets` 停止並列出代碼：

   ```bash
   npm run pipeline -- claims offsets --election <選舉代碼>
   npm run pipeline -- claims renumber --election <選舉代碼>
   npm run pipeline -- claims run --election <選舉代碼>
   ```

完成判準如下：

| 條件 | 證據 |
|---|---|
| 範圍內已轉錄的參選者都已編碼 | `claims progress` 的人數與編碼紀錄 |
| 每則主張的起訖都已填入 | `claims offsets` 沒有列出代碼 |
| 這個階段的核對通過，詞表沒有待審的詞 | `claims run` 的結束代碼是 0 |

<br>

## 判讀規則

### 拆分

一則主張只包含一個可以單獨同意或反對的政策。同一句原文含多項政策時拆成多則，各自截取對應的一段原文，數字與條件留在它所屬的那一則。拆分依下列規則：

- 要政府辦理的事建立主張。價值、自我介紹、經歷、已完成的政績，參選人本人提供的服務與問政的方式、以本人薪資或補助款辦理的事，以及政黨、民間團體自辦的事都略過。
- 口號與概括語依內容判斷：寫出政策立場、設施、項目或群體時建立主張，只寫建設、基礎建設、福利、政策領域，或只寫計畫名稱而看不出內容時略過。
- 標題與其下的項目一起閱讀，標題提供的對象或領域填入欄位，原文欄截取項目本身。
- 同一項政策在政見欄出現兩次時只建立一則主張。

### 欄位

主張表的各欄：

| 欄 | 寫法 |
|---|---|
| 代碼 | `{選區代碼}-{號次}-{三位序號}`，依原文出現的順序編號，由 `claims renumber` 重排 |
| 參選者 | 名冊的對象代碼 |
| 段落 | `transcripts.tsv` 的段落代碼 |
| 原文起、原文迄 | 先寫 -，由 `claims offsets` 填入 |
| 原文 | 段落中連續的一段，與轉錄稿一字不差，從條目編號與項目符號之後開始，在段落中只出現一次 |
| 主體、動作、對象、工具、受益、條件、數量、時程、財源 | 受控欄位，寫詞表已採用的名稱，多值以頓號分隔，原文沒有提到時寫 - |
| 現任政府計畫 | 是或否，見 [現任政府計畫](#現任政府計畫) |
| 理由 | 這則主張主張什麼，以及拆分或取捨的理由 |

每個受控欄位回答一個問題，一個概念只屬於一個欄位，數字本身留在原文欄，欄位只記錄種類：

| 欄位 | 回答的問題 | 判讀的例子 |
|---|---|---|
| 主體 | 誰執行這項政策 | 「下修選舉年齡」寫立法院，「國道延伸」「汰換台水的老舊管線」寫中央政府，「督促縣府興建運動中心」寫地方政府 |
| 動作 | 對對象做什麼改變，選最貼近原文的一個 | 「延至12歲」寫延長，「擴充疫苗基金」寫擴大，「爭取興建活動中心」寫新增 |
| 對象 | 政策作用在什麼事物上 | 「軍人加薪」的對象是軍人待遇，受益是軍人 |
| 工具 | 以什麼手段達成，可以多值 | 「透過科技研發、金融支持與碳定價」寫價格機制、產業政策 |
| 受益 | 原文點名或對象必然指向的受益群體 | 「青年購屋超低利貸款」寫青年、購屋者 |
| 條件 | 適用的門檻或前提 | 「（排富）」寫排富，「第三胎以上」寫胎次門檻，「拓寬 6 米以下的巷道」寫寬度門檻 |
| 數量 | 原文數字的種類 | 「達到GDP的3%」寫占國內生產毛額比例，「道路拓寬為 20 米」寫寬度 |
| 時程 | 原文時間安排的種類 | 「任內逐年達到」寫任期內、逐年 |
| 財源 | 經費從哪裡來 | 「每年國庫撥補」寫國庫撥補 |

容易寫錯的欄位依下列規則：

- 主體在原文沒有寫明時依政策的權責判斷：修法寫立法院，訂定或修正自治條例與地方議會自身的議事寫地方議會，中央權責的行政措施寫中央政府，地方權責的寫地方政府。設施依主管機關判斷，督促、監督某項政策時依那項政策判斷。
- 原文寫「爭取」「督促」時，動作寫被爭取、督促的那件事對對象的改變。
- 尺度用來界定適用範圍時寫條件，是要達到的規格時寫數量。
- 財源欄只寫原文寫出的經費來源，原文寫出的做法本身就是一種財源時照寫，做法用不到經費時寫 -。
- 標題提供的領域填入欄位：標題「長照保險」下的「成立中央長照保險局」，對象寫長照保險。

### 現任政府計畫

現任者延續執政團隊的計畫，而且公報發布時仍在立法或執行中，寫是，其餘寫否。現任者是名冊標為現任的參選人，執政團隊是這場選舉的職位所屬政府的行政部門：中央的選舉是總統與行政院，地方的選舉是該縣市或鄉鎮市的政府。判斷依下列規則：

- 原文寫持續推動、續辦或擴大執政團隊的方案，或寫出執政團隊已推出的方案名稱時寫是。只寫持續推動某項目標時寫否。
- 原文寫持續爭取、督促、關注或要求時，是參選人自己的爭取與監督，寫否。
- 原文以一句話概括延續全部施政時，各項仍依本身判斷，新建、新設的項目寫否。
- 上級政府的方案由執政團隊執行，或原文看不出是哪一級政府的方案時寫否，縣市政府執行中央的長照 2.0 屬於前一種。

## 核對

| 核對範圍 | 失敗條件 |
|---|---|
| 原文 | 段落不存在，原文不在段落中，起訖與段落的文字不符 |
| 受控欄位 | 寫了詞表沒有登錄或還在待審的詞 |
| 現任政府計畫 | 名冊沒有標為現任的參選者寫了是 |
| 方法與審核狀態 | 寫了沒有登錄的名稱 |
